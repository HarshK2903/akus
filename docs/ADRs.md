# Architecture decisions

1. **PostgreSQL only:** real PG16 development/test databases, Alembic versioning. No SQLite fallback for transactional proof.
2. **One synchronous transaction owner:** FastAPI + SQLAlchemy 2 + Psycopg 3. Worker shares package and database. No microservice infrastructure.
3. **Separate local identity table:** fictional demo identity can never be mistaken for an effective institutional appointment. Production fails closed. Phase 2 has separate roster, episodes, offices and institutional identity/session tables; fixture role labels grant no authority. Real Google protocol is implemented; live integration remains externally blocked.
4. **Forward-only migrations:** no destructive downgrade; keep immutable audit. Future corrections use additive migrations and versioned source records.
5. **Accessibility primitives:** Radix Dialog for mobile focus trap/restore; native table/forms and Lucide icons; blueprint light tokens. OpenAPI-generated types plus TanStack Query handle server reads and errors.
6. **Policy precedence:** V2.3 verified cross-year movement supersedes stale Q07 and product-scope sentences; current-pool release supersedes Q43's ORIGINAL wording. V2.4 mapping authority confirmed. Cross-topic retroactivity remains pending.
7. **Local operational evidence:** native PG/Vite/Uvicorn route is exercised; Compose independently built and booted from fresh containers; Caddy/API/database verified. Production, remote CI, backups/restore and provider contracts are not claimed tested.

8. **Effective source authority:** permanent person identity differs from employment episodes, home department, office and Admin grant. A source record does not create a login. The LOCAL/DEMO selector is presentation metadata only. All current effective authority is fetched from PostgreSQL. An explicit Admin grant is required for source writes, even for a Principal.
9. **Office intervals:** timestamptz `[from, until)` intervals and generated office group (ACTING_HOD → HOD) support a GiST exclusion on equal person, *different* DRC/HOD group, and overlapping interval. This is global across departments. A separate scoped exclusion prevents simultaneous holders of the same departmental office. Migration 0003 removes an accidental same-role cross-department restriction; A02 only mandates cross-role exclusivity. PostgreSQL documentation supports [btree_gist unequal operators](https://www.postgresql.org/docs/16/btree-gist.html) and [range exclusion constraints](https://www.postgresql.org/docs/16/rangetypes.html#RANGETYPES-CONSTRAINT).
10. **History and ending:** issued office fields cannot be updated/deleted. A source end can only shorten the interval, increments version, preserves original_until, and commits an immutable audit event and idempotency receipt together. Phase 2 source corrections preserve original issued facts through immutable revisions and explicit office supersession/replacement; they do not decide academic consequences. Employment `ends_before` is explicitly exclusive storage; this does NOT decide P-59 same-calendar-date exam/separation chronology.
11. **Command serialization:** take the shared identity/source advisory transaction lock, then lock actor and target rows in stable order and re-resolve current session/link/authority before changes or receipt replay. Linking, import commit and source corrections follow the same serialization order. Cross-department DRC/HoD exclusion also protects direct/imported SQL and competing writers. Runtime superuser/SQL access remains local-only; least-privilege production roles are not finished.
12. **Source-only transition boundary:** academic impact cases now exist (Phase 3). Office changes queue affected applications and never fabricate withdrawal, waiver, approval or quota movement. P-NEW-05/06 consequences remain POLICY_PENDING when the institution has not decided the transition. Principal overlap with departmental office is conservatively blocked as AUTHORITY_POLICY_PENDING, not escalated to a new approver.

13. **Provider identity versus source email:** issuer+subject is immutable and globally unique even after revocation. Official email assignments and provider-observed verified emails have separate histories. A changed email never moves a subject to another person. Replacement requires the exact old link and audited Admin reconciliation.
14. **Pending teaching acceptance:** source recording/import is authorized Admin stewardship. IO-02 acceptance, P-54 leap-day deadline and final Silver assessment remain separate pending/domain concerns. First teaching uses the true official date per episode/subject, never upload time.
15. **Recoverable handoff:** source inventories have a read-only check mode and preserve later policy notes. Traceability distinguishes local tests, external live UAT and later academic domains. Existing Docker volumes and historical QA evidence survive continuation.

16. **Schedule authority and immutable movement:** user-confirmed current HoD manual
    verification applies to one person/offering only; provider metadata never proves
    participation. Cross-year movement keeps the original topic, uses sorted pool
    locks and balanced ledger constraints, and retains source on unavailable target.
17. **Field-specific withdrawal validity:** source conflicts block admission. Withdrawal
    depends on accepted commencement, so a new exam-only observation must not block
    lawful release. Any newer conflicting commencement stays blocked. Offering/app
    locks, current allocation and immutable commencement audit serialize this choice.
